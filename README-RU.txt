СТЕЛС-СЕРВИС: ВРЕМЕННЫЙ ХОСТИНГ НА RENDER
========================================

Этот комплект — готовый репозиторий для Render. В нём есть сайт, админка,
Dockerfile и два варианта конфигурации. Аккаунт Render и репозиторий GitHub
создаёте вы: я не могу зарегистрировать их за вас (нужны ваша почта и
подтверждение), поэтому всё останое подготовлено до последнего шага.

Что внутри
----------
Dockerfile            сборка образа: PHP 8.4 + Apache +扩展 gd/mbstring
config/apache-site.conf  виртуальный хост, запрет доступа к служебным папкам
config/php.ini        безопасные настройки PHP, логи в stderr
bin/entrypoint.sh     старт: порт, постоянный диск, пароль, index.html
bin/make_config.php   создание config.php только с bcrypt-хешем пароля
bin/render_index.php  пересборка index.html из content.json при старте
site/                 сам сайт (скопирован из проверенной поставки)
render.yaml           Blueprint: платный план + постоянный диск (полная админка)
render-free.yaml      Blueprint: бесплатный план без диска
README-RU.txt         эта инструкция

ПОДГОТОВКА К ЗАГРУЗКЕ
---------------------
1. Создайте аккаунт на GitHub: https://github.com/signup
2. Создайте новый публичный или приватный репозиторий (можно с любым именем,
   например steel-serves-demo).
3. Загрузите в него СОДЕРЖИМОЕ этой папки (не саму папку deploy\render).
   В корне репозитория должны оказаться Dockerfile, render.yaml, site\ и т.д.
   Ни в коем случае не загружайте сюда build\admin-password.txt и архив
   из dist\ — они содержат стартовый пароль.
4. Убедитесь, что в репозитории НЕТ файла site\data\config.php: он создаётся
   контейнером при запуске. Если файл есть — удалите его перед коммитом.

НА ЧТО ОБРАТИТЬ ВНИМАНИЕ
------------------------
- Пароль админки задаётся переменной BM_ADMIN_PASSWORD. В render.yaml стоит
  sync: false, поэтому Render сам спросит значение при создании сервиса.
  Введите стартовый пароль из файла dist\ADMIN-PASSWORD-RU.txt (передан
  отдельно от этого комплекта) или придумайте новый — не короче 12 символов.
- Пароль НЕ записан ни в Dockerfile, ни в render.yaml, ни в site/.
  В config.php попадёт только необратимый bcrypt-хеш.
- Отправка писем отключена (BM_DISABLE_MAIL=1): заявки сохраняются в админке
  в разделе «Заявки» и не уходят на Gmail заказчика.
-imsя базы данных нет: контент хранится в site\data\content.json.

ВАРИАНТ 1: ПОЛНАЯ ВЕРСИЯ С СОХРАНЕНИЕМ ПРАВОК (рекомендуется)
-------------------------------------------------------------
1. Войдите в Render: https://dashboard.render.com
2. New + → Blueprint → подключите созданный GitHub-репозиторий.
3. Render найдёт render.yaml. Подтвердите создание.
4. В поле BM_ADMIN_PASSWORD введите стартовый пароль. Не пропускайте шаг:
   без него контейнер не запустится (это сделано специально).
5. Дождитесь деплоя. Откройте выданный адрес вида
   https://steel-serves-demo.onrender.com
6. Проверьте:
   - главная страница открывается;
   - /healthz отвечает «ok» (это проверка для Render);
   - /login открывает форму входа;
   - вход со стартовым паролем работает;
   - в админке можно сохранить правку и она видна на сайте.
7. Сразу смените пароль: «Настройки» → «Пароль».

Почему платный план: только у платных сервисов Render можно подключить
постоянный диск. Он смонтирован в /var/www/html/storage; при старте туда
копируются data/ и uploads/, а потом на них делаются символические ссылки.
Благодаря этому правки, загрузки и заявки не теряются при перезапуске.

ВАРИАНТ 2: БЕСПЛАТНЫЙ ДЕМО-ХОСТИНГ
-----------------------------------
1. Переименуйте render-free.yaml в render.yaml (старый render.yaml уберите
   из репозитория или переименуйте, например в render-paid.yaml).
2. Залейте изменение в GitHub — Render пересоберёт сервис.
3. Всё остальное — как в варианте 1.
Ограничение: у бесплатного плана нет постоянного диска. После перезапуска
(в том числе после 15 минут простоя) контент вернётся к исходному, а пароль
создастся заново из BM_ADMIN_PASSWORD. Для показа сайта заказчику этого
достаточно; для реальной работы лучше вариант 1.

ПОСЛЕ ПРОВЕРКИ
--------------
- Если демонстрация закончилась, удалите сервис в Render, чтобы не платить
  за простой, и отзовите доступ GitHub у Render в настройках аккаунта.
- Если решите оставить сайт надолго, перенесите его на hoster.by по
  docs\INSTALL-RU.txt из основного архива и укажите там домен заказчика.

ЧАСТЫЕ ОШИБКИ
-------------
«ERROR: set BM_ADMIN_PASSWORD» — не задана переменная окружения.
«502 Bad Gateway» — контейнер ещё стартует; подождите 30–60 секунд и
  обновите страницу. Если не помогло — смотрите Logs сервиса.
Сайт открывается, но /login даёт 404 — не подключился mod_rewrite;
  проверьте, что в образе выполнен a2enmod rewrite (есть в Dockerfile).
Правки исчезли после рестарта — вы используете бесплатный план без диска.

ПРОВЕРКИ
--------
Локальные проверки (без реального деплоя):
  python build\test_deploy.py
Они проверяют конфигурацию контейнера, отсутствие секретов и работу
.administration через локальный Apache. Результат — в SECURITY-CHECKS-RU.txt.


ВРЕМЕННАЯ ПРОВЕРКА ПОЧТЫ
------------------------
В render.yaml добавлена переменная BM_LEAD_EMAIL = udomanskaya99@mail.ru.
Это получатель заявок ТОЛЬКО для писем: на сайте этот адрес не показывается,
там остаётся контакт заказчика. После проверки уберите строку BM_LEAD_EMAIL
из render.yaml и залейте изменение — then получателем снова станет e-mail
из раздела «Сайт и контакты».

Чтобы письмо действительно ушло, на Render нужно дополнительно:
1. Открыть сервис → Settings → Environment.
2. Найти BM_DISABLE_MAIL и заменить 1 на 0 (или удалить переменную).
3. Save Changes — сервис перезапустится.

ВНИМАНИЕ: на onrender.com нет почтового ящика на домене, поэтому отправитель
no-reply@steel-serves.by не существует. Письмо может не отправиться или
попасть в спам. Гарантированно почта работает только на настоящем хостинге
(hoster.by), где создан ящик отправителя и настроены SPF/DKIM.
